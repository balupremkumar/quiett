# Voice Dictation — TaskFlow Direct-Capture Handover

Status: proposed, not yet implemented. Generated by a Claude Code session in
the TaskFlow repo (`D:\Dev\ai\projects\active\to-do-app`) for a separate
Claude Code session rooted in `D:\Dev\ai\projects\active\voice-dictation` to
implement. No code in voice-dictation was touched to produce this document.

## What this asks for

Add a feature to voice-dictation: after the existing transcribe + postprocess
pipeline produces text, detect a trigger phrase (configurable list; the
primary one the user actually wants to say is **"add this to TaskFlow"**,
with "add to my to-do list" and "add a task" as additional defaults), and if
matched, route the phrase-stripped remainder to TaskFlow's local HTTP API as
a new task instead of pasting it.

## The contract (frozen, already implemented and verified on the TaskFlow side)

- Port discovery: `%APPDATA%\TaskFlow\port.json` → `{"port": <int>, "pid": <int>, "startedAt": "<iso8601>"}`
- Install-path discovery: `%APPDATA%\TaskFlow\app-path.json` → `{"exePath": "<string>"}`
- Health check: `GET http://127.0.0.1:<port>/health` → `200 {"status":"ok"}`
- Task creation: `POST http://127.0.0.1:<port>/tasks`, body
  `{"title": "<string, required>", "notes"?: string, "dueDate"?: "yyyy-MM-dd",
  "priority"?: "none"|"low"|"medium"|"high", "projectId"?: string, "source"?: string}`
  → `201` with the created task as JSON.
- Use `"source": "voice-dictation"` on every task created via this feature.
- Hidden launch: `TaskFlow.exe --hidden` starts straight into tray, no window.

## Proposed feature behavior

1. Same Ctrl+Alt hotkey — no new hotkey.
2. After transcribe + postprocess, check the final text against a
   configurable list of trigger phrases (case-insensitive, matched at the
   start of the text). Defaults, in priority order: "add this to TaskFlow"
   (the phrase the user actually intends to say day-to-day), "add to my
   to-do list", "add a task".
3. Match → strip the phrase, route the remainder as the task title into a
   relabeled version of the existing edit-before-paste preview panel (title
   "Add Task", confirm button "Add Task" instead of "Insert", still editable).
4. Confirm → `GET /health`, then `POST /tasks` with `source: "voice-dictation"`.
   If the health check fails/times out: show "TaskFlow isn't running" inline
   and fall back to normal clipboard paste of the raw text — nothing lost.
5. No match → existing paste behavior, completely unchanged.
6. New `config.json` fields: trigger phrase list (array of strings),
   enable/disable toggle — follow the existing hot-reload config pattern
   already in this codebase.
7. One-click launch coupling: on voice-dictation's own startup, fire an async,
   non-blocking health check (short timeout — must never delay voice-dictation's
   own startup). If unhealthy/missing and `app-path.json` exists, launch
   `<exePath> --hidden` in the background and retry the health check a couple
   times with backoff. If `app-path.json` doesn't exist, skip silently —
   voice-dictation must work standalone regardless of whether TaskFlow is
   installed; this is a bonus integration, never a hard dependency.

## How to test (once implemented)

1. Start TaskFlow (or let voice-dictation's launch-coupling start it).
2. Hold Ctrl+Alt, say "add this to TaskFlow buy milk", release.
3. Preview shows "Add Task: buy milk", editable.
4. Confirm → task appears in TaskFlow's UI with `source: "voice-dictation"`.
5. Repeat with one of the secondary phrases, e.g. "add to my to-do list call
   the dentist" → same behavior, confirming multiple configured phrases work.
6. Quit TaskFlow, repeat step 2 → preview shows "TaskFlow isn't running"
   and falls back to paste behavior instead of erroring.
7. Quit TaskFlow entirely (including tray), restart voice-dictation → confirm
   TaskFlow auto-launches hidden within a few seconds, tray icon appears.
8. Say a normal sentence with no trigger phrase → confirm normal paste
   behavior, completely unaffected.

## Known gotchas to expect

- TaskFlow's API is loopback-only (127.0.0.1), no auth, by design — don't add credentials.
- `port.json`'s port can change between TaskFlow restarts (OS-assigned
  fallback if the default port is taken) — always re-read `port.json` fresh,
  don't cache the port across voice-dictation's own restarts.
- TaskFlow's uninstaller does not delete `%APPDATA%\TaskFlow` — if
  `app-path.json` points at an exe that's since been uninstalled, the launch
  attempt will simply fail; treat that the same as "TaskFlow not installed"
  (skip silently for the auto-launch path; show "not running" for the capture path).

## Out of scope for this feature

- Local LLM-based command parsing (deferred indefinitely on the TaskFlow side
  too — see TaskFlow's `2026-06-24-app-shell-tech-stack-design.md` §4).
- Any reverse coupling — TaskFlow never launches or depends on voice-dictation.
